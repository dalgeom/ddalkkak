# 스레드 본문 형식

`게시-기록.md`는 **무엇을** 올렸는지만 적는다. 이 파일은 **어떻게** 쓰는지를 적는다.
이게 없어서 1주차(텍스트만 올리던 시기) 형식을 8/24에 그대로 끌어와 문제를 본문에
또 적는 사고가 났다.

## 절대 규칙

**문제는 카드 이미지로 첨부한다. 본문에 문제를 다시 적지 않는다.**

2026-08-06부터 이미지 게시로 바뀌었다. 그 전(8/04~8/05)에는 본문에 문제를 적었고,
`스레드-첫주.md`에 그 시절 원고가 남아 있다 — **그건 지금 형식이 아니다.**

## 본문 구조

```
[지난] 문제 정답입니다.

답은 「○○」 — 한 줄 해설.
왜 그렇게 되는지 한두 줄.

[댓글 반응 한 줄 — 핸들은 적지 않는다]

오늘 건 ○○입니다.
문제를 적지 말고, 어디서 막히는지만 한 줄로 흘린다.

→ ddalkkak.app
```

- **정답 공개가 먼저.** 새 문제가 아니라 지난 문제 답으로 글을 연다.
- **오늘 문제 설명은 한 줄.** 카드에 다 있으니 "첫 줄만 보면 뻔한데 둘째 줄에서
  무너진다" 식으로 어디가 함정인지만 흘린다.
- **본문에 핸들을 태그하지 않는다.** "네 분이 다 찾아내셨습니다"처럼 수만 적는다.
  개인 반응은 각 댓글의 답글로 따로 한다.
- 정답 공개 시점: 다음 게시일 아침 본문. 금요일 문제는 **월요일** 공개(주말 미게시).

## 링크는 그냥 ddalkkak.app

UTM을 붙이지 않는다. 2026-08-26에 21일치를 재 보니 **모든 채널이 이미 리퍼러로
잡히고 있었다** — 스레드 25세션, 네이버 블로그 36, 페이스북 7, 인스타 3. 「인앱
브라우저가 리퍼러를 안 붙인다」는 8/25의 진단이 이 사이트에서는 틀렸다.

같은 기간 `(not set)`은 14세션인데 **참여율 0%**다(다른 채널은 30~76%). 사람이 아니라
봇이고, UTM으로 잡을 수 있는 대상이 아니다.

실익이 없는데 비용은 있었다 — 8/25 스레드에서 붙여넣다 흘렸고, URL이 지저분해
클릭 의욕이 떨어지고, 입으로 전할 수도 없다.

## 답글 규칙

- **답글에 정답을 쓰지 않고, 맞았다 틀렸다 판정도 하지 않는다.** 공개는 본문에서만.
- 4명이 달았으면 답글 4개를 각각 다르게 쓴다. 복붙 금지.
- 재방문 댓글러는 기록에서 확인해 인사를 더한다.

## 카드 만들기

```
node scripts/social-card.mjs 2026-08-24
```

`scripts/social-card.mjs` 위쪽 `CARDS`에 날짜별로 `{ id, chip, 물음, 줄 }`을 넣는다.
`줄`은 4줄 안쪽이 예쁘게 들어간다. 결과는 `promo/social/스레드-YYYY-MM-DD.png`.

## 문제 고르기

- 그림·도형이 필요한 유형(lcd·figure)은 카드에 못 담는다. 텍스트/pre만.
- **인터넷에 널린 넌센스는 쓰지 않는다.** 8/24에 "정우네 어머니 셋째 이름" 카드를
  만들었다가 갈아치웠다 — 다들 아는 문제는 딸깍 수준을 깎아먹는다.
- 규칙 찾기(발견형)가 제일 좋다. 사이트 정체성이고, 첫 줄에서 세운 가설이 둘째
  줄에서 무너지는 구조가 댓글을 부른다.
- 후보 뽑기: 텍스트만 쓰고 줄이 짧은 문제를 `problems.ts`에서 골라 쓴다.
