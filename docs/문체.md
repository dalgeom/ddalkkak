# 딸깍 문체 규칙

2026-09-29 결정. **사용자에게 보이는 글은 해요체로 통일한다.**

## 왜

같은 페이지 안에서 말투가 갈아탔다. 상식 분야 페이지는 위쪽 소개가 「~모았습니다」인데
바로 아래 본문 369문장 중 267문장(72%)이 「~이다」「~었다」였다. 발견형 분야 소개글은
148문장 중 123문장(83%). 읽을거리도 합니다체 사이에 「…붙여 본다.」 같은 한다체 요약
문장이 섞였다. 사람이 쓴 글처럼 읽히지 않는다 — 애드센스 반려(8/11·8/21)의 원인이라고
단정할 수는 없지만, 「가치가 별로 없는 콘텐츠」 판정에 보태질 수 있는 감점이다.

## 규칙

**1. 문장은 해요체로 끝낸다.** 「~해요 · ~이에요 · ~예요 · ~죠 · ~까요?」.
「~습니다」(합니다체)도 「~다」(한다체)도 쓰지 않는다. 소제목도 「~다」로 끝내지 않는다 —
명사로 끝내거나(「두 글자가 어려운 이유」) 해요체로 쓴다.

| 전 | 후 |
|---|---|
| 정답은 8입니다. | 정답은 8이에요. |
| 그런데 하루를 너무 많이 넣었다. | 그런데 하루를 너무 많이 넣었어요. |
| 순서가 선다. | 순서가 잡혀요. |
| 초성 두 개는 361칸뿐이다 (소제목) | 초성 두 개는 361칸뿐 |

**2. 대시(—)를 쓰지 않는다.** 한국어 글에는 거의 없는 부호다. 문장을 나누거나, 쉼표·괄호로
바꾼다. 예외는 페이지 제목(`<title>`)의 부제 구분뿐이다.

**3. AI 글 버릇을 줄인다.** 검사기가 잡지는 않지만 고칠 때 같이 본다.
- 「A가 아니라 B예요」 대비를 문단마다 쓰지 않는다. 반전은 한 글에 한두 번이면 된다.
- 마지막 문단에서 교훈을 다시 요약하지 않는다(「정리하면…」「…이 곧 전부예요」).
- 「~거든요」「~죠」를 연달아 쓰지 않는다. 해요체의 기본은 「~해요」다.
- 숫자 괄호(「(시도 64)」)가 본문에 빽빽하면 표나 예시 블록으로 뺀다.

**4. 사실은 한 글자도 바꾸지 않는다.** 말투를 고칠 때 숫자·연도·정답·태그는 그대로다.
`scripts/style-check.ts compare`가 고치기 전후의 숫자·태그를 대조한다.

## 예외

- **예시 블록(`<pre>`)·그림(SVG)·코드** — 문장이 아니다. 검사도 안 한다.
- **힌트** — 명사형 한 줄(「목이 가장 긴 동물」)은 그대로 둔다. 문장이면 해요체.
- **개인정보처리방침·이용약관** — 법률 문서는 합니다체가 표준이다. 대상에서 뺀다.
- **코드 주석·커밋·내부 문서(promo/·docs/)** — 사용자에게 안 보인다. 이 문서도 한다체다.

## 도구

```
npx vite-node scripts/style-check.ts snapshot before.json         # 고치기 전에 떠 둔다
npx vite-node scripts/style-check.ts compare before.json fields   # 사실 바뀜·남은 위반
```

`src/lib/style.test.ts`의 `ENFORCED`에 고친 범위를 넣으면, 그 범위에서 「~다.」나 대시가
다시 나올 때 CI가 깨진다. 범위: `fields`(분야·유형 페이지) → `articles`(읽을거리) →
`explains`(문제 해설·힌트). 검사 대상 목록은 `src/lib/styleTexts.ts`.
